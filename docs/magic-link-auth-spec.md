# Design Specification: Passwordless Magic-Link Authentication

This specification defines the exact database schema, store API, HTTP endpoints, email content, UI templates, configuration, and test matrix for replacing email+password authentication with magic-link login on Nacfson Cloud. The companion implementation plan is [magic-link-auth-plan.md](./magic-link-auth-plan.md).

Scope note: sessions, cookies, `GET /verify` ingress auth, `RequireAuth` middleware, internal `/api/internal/*` endpoints, and the manager are **out of scope** — they are unchanged.

## 1. Database

### 1.1 New table `login_tokens`

Added to the `schema` constant in `internal/auth/store.go` (applied by `Store.Migrate`, which is idempotent):

```sql
CREATE TABLE IF NOT EXISTS login_tokens (
    token_hash TEXT PRIMARY KEY,
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    expires_at TIMESTAMPTZ NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_login_tokens_user ON login_tokens(user_id);
```

- `token_hash` is the hex-encoded SHA-256 of the raw token. Raw tokens are never persisted.
- One row per outstanding link. Requesting a new link deletes the user's prior rows first, so at most one link is valid per user at any time.

### 1.2 Existing tables

- `users.password_hash` is already nullable; magic-link users are created with `''`. The column is dropped only in the final cleanup phase (§9).
- `email_verifications` stops receiving writes as soon as the new flow ships; the table is dropped in cleanup (§9).
- `sessions`, `projects`, `project_members`, `audit_events`: unchanged.

## 2. Token format and lifecycle

| Property | Value |
|---|---|
| Raw token | 32 random bytes, hex-encoded (64 chars) — generated by the existing `NewAuthCode()` in `internal/auth/authcode.go` |
| Stored form | hex SHA-256 of the raw token (`NewAuthCode` already returns both) |
| TTL | 15 minutes |
| Use count | Exactly once, enforced atomically (§3, `ConsumeLoginToken`) |
| Concurrency | New request invalidates all previous tokens for that user |
| Expiry cleanup | Ticker goroutine in `cmd/auth/main.go` calls `DeleteExpiredLoginTokens` every 10 minutes |

Lifecycle: `POST /login` creates → email delivers → `GET /magic` displays (does not consume) → `POST /magic` consumes (deletes row) → session created. Expired or already-consumed tokens fail closed to `/login` with an error message.

## 3. Store API (`internal/auth/store.go`)

```go
// LoginToken is a pending one-time sign-in token.
type LoginToken struct {
    UserID    string
    TokenHash string
    ExpiresAt time.Time
    CreatedAt time.Time
}

func (s *Store) CreateLoginToken(ctx context.Context, userID, tokenHash string, expiresAt time.Time) error
// INSERT INTO login_tokens (token_hash, user_id, expires_at) VALUES ($1, $2, $3)

func (s *Store) ConsumeLoginToken(ctx context.Context, tokenHash string) (*LoginToken, error)
// DELETE FROM login_tokens
// WHERE token_hash = $1 AND expires_at > now()
// RETURNING user_id, token_hash, expires_at, created_at
// Returns (nil, nil) when no row matched (unknown, expired, or already consumed).
// The single-statement DELETE ... RETURNING makes double-redemption impossible.

func (s *Store) DeleteLoginTokensByUserID(ctx context.Context, userID string) error
// DELETE FROM login_tokens WHERE user_id = $1

func (s *Store) LatestLoginTokenCreatedAt(ctx context.Context, userID string) (*time.Time, error)
// SELECT max(created_at) FROM login_tokens WHERE user_id = $1
// Returns (nil, nil) when the user has no outstanding tokens.

func (s *Store) DeleteExpiredLoginTokens(ctx context.Context) (int64, error)
// DELETE FROM login_tokens WHERE expires_at <= now()
```

Removed in cleanup (§9): `CreateEmailVerification`, `GetEmailVerification`, `DeleteEmailVerification`, `DeleteEmailVerificationsByUserID`, `UpdateUserPassword`.

## 4. Mailer (`internal/auth/mailer.go`, new file)

Extracts the SMTP block currently duplicated twice in `Register`:

```go
type Mailer struct{ cookieDomain string }

func NewMailer(cookieDomain string) *Mailer

// Configured reports whether SMTP_HOST is set.
func (m *Mailer) Configured() bool

// Send delivers a plaintext email. Reads SMTP_HOST, SMTP_PORT (default "25"),
// SMTP_USER, SMTP_PASS (fallback SMTP_PASSWORD), SMTP_FROM (default
// "noreply@" + cookieDomain) — identical semantics to the current inline code.
func (m *Mailer) Send(to, subject, body string) error
```

Callers invoke `Send` inside `go func(){ ... }()` with error logging, matching current behavior.

### 4.1 Magic-link email content

```
Subject: Sign in to nacfson.cloud

Click the link below to sign in:

https://{host}/magic?token={raw}&rd={url-escaped rd}

This link expires in 15 minutes and can be used once.
If you did not request it, you can safely ignore this email.
```

`{host}` is `r.Host` of the originating request (same approach as the current verification link).

## 5. HTTP endpoints (`internal/auth/handler.go`)

### 5.1 Route table after the change

| Method & path | Handler | Status |
|---|---|---|
| `GET /login` | `LoginForm` | modified (email-only form) |
| `POST /login` | `RequestMagicLink` | replaces password `Login` |
| `GET /link-sent` | `LinkSent` | new (replaces `/verification-sent`) |
| `GET /magic` | `MagicForm` | new |
| `POST /magic` | `MagicConsume` | new |
| `POST /logout` | `Logout` | unchanged |
| `GET /register`, `POST /register` | redirect | `301` → `/login` (preserving `rd`) |
| `GET /verify-email` | redirect | `301` → `/login` |
| `GET /verify`, internal APIs, `GET/DELETE /api/auth/*` | — | unchanged |
| `POST /api/auth/magic-link` | `APIMagicLink` | new (§6) |
| `POST /api/auth/session` | `APILogin` | kept, deprecated until cleanup (§9) |

### 5.2 `GET /login` — `LoginForm`

Unchanged contract: validates `rd` via `validateReturnTo`, renders `login.html` with `ReturnTo` and `Error`. The template no longer has a password field (§7.1).

### 5.3 `POST /login` — `RequestMagicLink`

Form fields: `email`, `return_to`.

1. `http.MaxBytesReader` 1 MiB; `ParseForm`; on error redirect `/login?error=invalid request`.
2. Normalize email: `strings.ToLower(strings.TrimSpace(...))`; validate with `mail.ParseAddress` requiring `addr.Address == email`; on failure redirect `/login?error=invalid email address`.
3. Validate `return_to` with `validateReturnTo(returnTo, cookieDomain, allowedRedirects)`; on failure fall back to the default destination (same pattern as today).
4. Rate limit via `loginAllowed(r, email)` (existing IP+email limiter, 5/min default); if exceeded redirect `/login?error=too many attempts`. Every request records an attempt via `recordFailedLogin` — with passwordless login each send is a mailbox hit, so all sends count toward the limit, not just failures.
5. `GetUserByEmail`; if nil, `CreateUser(ctx, email, "", false /*admin*/, false /*verified*/)`.
6. Resend throttle: if `LatestLoginTokenCreatedAt` is within 60 seconds, **skip steps 7–8 silently** and continue to step 9 (uniform response; no oracle for "email exists and recently requested").
7. `DeleteLoginTokensByUserID(user.ID)`, then `NewAuthCode()` → `CreateLoginToken(user.ID, hash, now+15m)`.
8. Build the link and send via `Mailer` (async goroutine). If `!mailer.Configured()`, print the link to stdout (dev fallback).
9. Redirect `302` → `/link-sent?rd={rd}`; in the dev fallback also append `&token={raw}` (mirrors current `/verification-sent` behavior).

Response is identical whether the account existed, was created, or was throttled: no account enumeration.

### 5.4 `GET /link-sent` — `LinkSent`

Renders `link_sent.html` with `ReturnTo`, and — only when SMTP is not configured and `token` is present — `MagicLink` = `/magic?token={token}&rd={rd}` so local development works without a mail server.

### 5.5 `GET /magic` — `MagicForm`

Query params: `token`, `rd`. **Does not touch the database.** Renders `magic.html`, which contains a form with hidden `token` + `rd` fields posting to `/magic` and a "Continue to sign in" button. Missing `token` → redirect `/login?error=invalid sign-in link`.

Rationale: corporate mail scanners and link-preview bots prefetch GET URLs; if GET consumed the one-time token, the user's click would find it already used.

### 5.6 `POST /magic` — `MagicConsume`

Form fields: `token`, `return_to`.

1. `ConsumeLoginToken(HashSessionToken(token))`. Nil result → redirect `302` → `/login?error=link expired or already used`.
2. `VerifyUser(lt.UserID)` — first sign-in doubles as email verification.
3. `NewSessionToken()` → `CreateSession(lt.UserID, hash, sessionTTL)` → `SetSessionCookie(w, token, sessionTTL, cookieDomain)` — identical tail to the current `VerifyEmail`.
4. Validate `return_to` via `validateReturnTo`, defaulting to `/` on failure, and `302` there.

Store/DB errors anywhere → `500` with logging, matching existing handler conventions.

### 5.7 Removed handlers

`Login` (password), `Register`, `RegisterForm`, `VerificationSent`, `VerifyEmail`, plus the `bcrypt` import in `handler.go`.

## 6. JSON API for external consumers

Project PN currently authenticates with `POST /api/auth/session` `{email, password}`. Transitional contract:

### 6.1 `POST /api/auth/magic-link` — `APIMagicLink` (new)

- CORS-gated by the existing `allowAPIOrigin`; rate-limited like §5.3.
- Request: `{"email": "user@example.com", "redirect": "https://app.nacfson.cloud/after-login"}`. `redirect` passes through `validateReturnTo`.
- Response: always `202 {"status":"sent"}` for well-formed requests (anti-enumeration), `400` for malformed JSON/email, `403` for disallowed origin, `429` when rate-limited.
- The emailed link targets the central `/magic` page. After consumption the shared `nacfson_session` cookie (domain `COOKIE_DOMAIN`) is set and the browser is redirected to the validated `redirect`; the consumer app then reads the cookie session or calls `GET /api/auth/session`.

### 6.2 `POST /api/auth/session` — `APILogin` (deprecated)

Kept byte-for-byte compatible until Project PN migrates, then removed (§9). `GET /api/auth/session`, `GET /api/auth/me`, `DELETE /api/auth/session`: unchanged.

## 7. UI templates (`web/templates/`)

All pages reuse the existing glassmorphic dark theme of `login.html`. Vanilla CSS only.

### 7.1 `login.html` (modified)

- Inputs: `email` (type=email, required, autofocus), hidden `return_to`.
- Removed: password field, "Register" link (single unified flow).
- Submit: `POST /login`, button label "Send sign-in link".
- Renders `{{.Error}}` from the query string as today.

### 7.2 `link_sent.html` (new)

- Copy: "Check your email — we sent you a sign-in link. It expires in 15 minutes."
- When `{{.MagicLink}}` is set (dev fallback only): renders the link directly for local testing.

### 7.3 `magic.html` (new)

- Copy: "Continue to sign in to nacfson.cloud".
- Form: hidden `token`, hidden `return_to`, submit `POST /magic`, button label "Continue".

### 7.4 Deleted

`register.html`, `verification_sent.html`.

## 8. Bootstrap, sync-admins, configuration, Kubernetes

### 8.1 `cmd/auth/main.go`

- `bootstrapAdmin` creates `BOOTSTRAP_ADMIN_EMAIL` with `password_hash=''`, `is_admin=true`, `is_verified=true`. `BOOTSTRAP_ADMIN_PASSWORD` is no longer read.
- Starts the `DeleteExpiredLoginTokens` ticker (10 min interval, stopped on shutdown).

### 8.2 `cmd/sync-admins/main.go`

Input YAML becomes a plain list of emails:

```yaml
admins:
  - alice@example.com
  - bob@example.com
```

Upserts each as `is_admin=true`, `is_verified=true`, no password. bcrypt dependency dropped from this binary.

### 8.3 Environment variables

| Variable | Change |
|---|---|
| `SMTP_HOST/PORT/USER/PASS|PASSWORD/FROM` | unchanged semantics, but now **required in production** — without them nobody can sign in (existing sessions survive their 7-day TTL) |
| `BOOTSTRAP_ADMIN_PASSWORD` | removed |
| `MAGIC_LINK_TTL` | optional, default `15m` (flag `-magic-link-ttl` on `cmd/auth`) |
| everything else (`COOKIE_DOMAIN`, `AUTH_INTERNAL_TOKEN`, `AUTH_API_ALLOWED_ORIGINS`, `AUTH_ALLOWED_REDIRECTS`, `DATABASE_URL`, …) | unchanged |

### 8.4 Kubernetes (`k8s/auth/`)

- New `smtp-secret.yaml` (values supplied at deploy time) referenced by `deployment.yaml` via `envFrom`/`env`.
- `bootstrap-secret.yaml`: drop `BOOTSTRAP_ADMIN_PASSWORD`.
- `admin-users-secret.yaml`: email-list format (§8.2).
- README gains a "magic-link login requires a working SMTP relay" note.

## 9. Cleanup phase (after Project PN migrates to §6.1)

1. Remove `POST /api/auth/session` (password) and `apiLoginRequest.Password`.
2. Guarded migrations: `DROP TABLE IF EXISTS email_verifications;` and `ALTER TABLE users DROP COLUMN IF EXISTS password_hash;`.
3. Remove the store methods listed in §3, then `golang.org/x/crypto/bcrypt` from `go.mod`; `go mod tidy`.

## 10. Security requirements

1. Raw tokens: ≥32 random bytes; only SHA-256 hashes persisted.
2. Single use enforced by atomic `DELETE ... RETURNING`; 15-minute TTL; one active token per user.
3. `GET /magic` performs no state change (scanner-safe).
4. Uniform "check your email" responses; no account-existence oracle in HTML or JSON flows.
5. Link requests rate-limited per IP+email (existing limiter) plus a 60-second per-email resend throttle.
6. All redirect targets (`rd`, `return_to`, API `redirect`) validated by `validateReturnTo`.
7. Session cookie unchanged: HttpOnly, Secure, SameSite=Lax, domain-scoped, hashed in DB.

## 11. Test matrix

### Store (`store_test.go`, needs `AUTH_DATABASE_URL`)

| Case | Expectation |
|---|---|
| Create + consume valid token | returns row, row deleted |
| Consume same token twice | second call returns `(nil, nil)` |
| Consume expired token | `(nil, nil)`, row remains until sweep |
| `DeleteLoginTokensByUserID` | removes all rows for user only |
| `LatestLoginTokenCreatedAt` | max created_at; nil when none |
| `DeleteExpiredLoginTokens` | removes only expired rows, returns count |

### Handlers (`handler_test.go`)

| Case | Expectation |
|---|---|
| `POST /login` existing user | 302 `/link-sent`, token row created, prior tokens deleted |
| `POST /login` unknown email | identical response; unverified user created |
| `POST /login` invalid email | 302 `/login?error=invalid email address`, no user created |
| `POST /login` within 60s resend window | identical redirect, no new token row |
| `POST /login` over rate limit | 302 `/login?error=too many attempts` |
| `GET /magic` | 200, token row still present |
| `POST /magic` valid token | user verified, session row created, cookie set (HttpOnly/Secure/Lax), 302 to validated `rd` |
| `POST /magic` expired/reused/garbage token | 302 `/login?error=link expired or already used` |
| `POST /magic` malicious `return_to` | redirect falls back to default destination |
| `GET/POST /register`, `GET /verify-email` | 301 → `/login` |
| `POST /api/auth/magic-link` allowed origin | 202 regardless of account existence |
| `POST /api/auth/magic-link` disallowed origin | 403 |
| Existing session/bearer/`/verify`/internal API tests | still green, unmodified |
